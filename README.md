# Coder Nexus

**Agent roles, skills and MCP tools that help an AI coding agent deliver software the way a team does: requirements → design → plan → code → review → verification.**

Coder Nexus has three parts:

- **VS Code / Antigravity extension**: copies agent roles, skills and rules into your project and gives you one-click commands to manage them.
- **`coder-nexus` CLI (Python Hub)**: the MCP server your agent talks to, plus terminal commands for task intake, UI/UX design and environment checks.
- **`skill-factory` CLI** *(new in 3.0)*: generators that write skills tailored to *your* workspace (architecture, clean code, tests, review, security, QA…). Installed together with `coder-nexus`.

Installing it does not start anything on its own. Your host agent (for example Antigravity) reads the installed roles and skills and uses them when you ask it to work.

## How it works

```
Your request / task ticket
        │
        ▼
 Spec Writer ──► Designer (UI/UX) ──► Planning ──► Code Writer ──► Code Reviewer ──► Test Runner ──► Docs Writer
        │               │                │
   you approve     you approve      you approve
```

| Concept | What it means |
|---|---|
| **Agent roles** | Each role owns one step of delivery and hands its output to the next. |
| **Approval gates** | You approve requirements, design and the implementation plan before code is written. Agents never approve for you. |
| **Skills & rules** | Step-by-step guidance the agent follows for each step (discovery, design, coding, review, evidence). |
| **Stack packs** | Rules and skills for a specific stack (Flutter, Backend, Frappe UI). A workspace can hold several packs, e.g. a monorepo with an app and an API. |
| **Workspace skills** | Skills generated by the Skill Factory into `.agents/skills/`. They belong to your project and take priority over pack skills on the same topic. |
| **MCP tools** | Task intake, architecture guidance, UX patterns and validators the agent can call. |
| **Work items** | Each piece of work is stored as files under `.superpowers/work-items/<slug>/vN/`, so every decision is reviewable. |

## Install

### 1. Install the extension
In VS Code / Antigravity open **Extensions** (`Cmd+Shift+X` / `Ctrl+Shift+X`), search **Coder Nexus** and click **Install**.
Or download a `.vsix` from [Releases](https://github.com/pzakhim/coder-nexus/releases) and use **Extensions → … → Install from VSIX...**.

### 2. Install the CLI
Click **Coder Nexus** in the status bar → **Install / Update CLI**. It installs [`uv`](https://docs.astral.sh/uv/) if needed, then the CLI matching the extension version.

Manual install:

```sh
curl -LsSf https://astral.sh/uv/install.sh | sh
```

```sh
uv tool install --force git+https://github.com/pzakhim/coder-nexus.git@vX.Y.Z
```

```sh
coder-nexus --help
```

On Windows, install `uv` with `powershell -c "irm https://astral.sh/uv/install.ps1 | iex"`. Replace `X.Y.Z` with your extension version. Run **Install / Update CLI** again after each extension update.

### 3. Add agents to your project
Open your project. If the extension detects a supported stack it offers **Sync Now**. Otherwise open the Command Palette (`Cmd+Shift+P` / `Ctrl+Shift+P`) and run **Coder Nexus: Sync Stacks to Workspace (Auto-Detect)**, then tick the stacks you use.

The sync writes:

| Path | Content |
|---|---|
| `.agents/agents/` | The agent roles, combined with the rules of each selected pack |
| `.agents/plugins/coder-nexus/` | Shared skills and stack skills |
| `.agents/stack.json` | Which pack owns which folders (edit it if detection guessed wrong) |

Re-run the sync after installing or updating the CLI so the MCP config points to it.

### 4. Check your setup

```sh
coder-nexus doctor
```

## Using it

Once synced, talk to your agent as usual, for example *"Implement task ABC-12"* or *"Add a settings screen"*. The agent follows the roles and stops at each approval gate for you to review.

### Task intake (optional)
Connect a task tracker so agents can read tickets. Credentials go into the project's local `.env`. **Make sure `.env` is in `.gitignore`.**

| Command | What it does |
|---|---|
| `coder-nexus setup huly` | Guided setup: workspace URL, then login |
| `coder-nexus setup huly --check` | Check that the configuration is complete (read-only) |
| `coder-nexus setup huly --reset` | Start setup again (e.g. expired session) |
| `coder-nexus my-tasks` | List your open tasks (`--all` for the whole workspace) |
| `coder-nexus task-detail <ID>` | Show a task with its acceptance criteria |
| `coder-nexus task-detail <ID> --download` | Also save attachments and linked designs under `.superpowers/sources/<ID>/` |

You can also just ask the agent to *"set up Huly"*.

### Figma frames (optional, read-only)
Add `FIGMA_TOKEN=…` to `.env`. Linked frames are then downloaded with `task-detail --download`, or fetch one directly:

```sh
coder-nexus figma fetch "https://www.figma.com/design/<key>/<name>?node-id=<id>"
```

### Stack setup

```sh
coder-nexus setup flutter --check
```

```sh
coder-nexus setup flutter --profile external-standard
```

Profiles tell the agent where a Flutter project's shared building blocks come from:

| Profile | Use when the project… |
|---|---|
| `external-standard` | has no shared component library; use standard framework widgets |
| `external-structured` | has its own design system or shared components; reuse them |

### UI/UX design
Any change the user can see gets a design you approve before coding. The designer agent drives these commands; you can run them yourself too:

| Command | What it does |
|---|---|
| `coder-nexus ux extract --project .` | Detect the project's look and generate an HTML kit |
| `coder-nexus ux viewports --project .` | Set the mockup sizes (mobile / tablet / web) |
| `coder-nexus ux new --work-item <dir> --title "<Feature>"` | Create a design folder for a work item |
| `coder-nexus ux screen …` / `ux component …` | Add a screen or a new component |
| `coder-nexus ux sync --work-item <dir>` | Rebuild the interactive preview |
| `coder-nexus ux validate --work-item <dir>` | Check the design before approval |

Open `design-uiux/index.html` in the work item to click through the flows.

### Skill Factory (new in 3.0)
Fixed packs give every project the same rules. The Skill Factory instead gives you **generators**: each one studies your workspace, asks you to confirm the key decisions, and writes a skill that fits your code, stack and conventions. The generated skill lives in `.agents/skills/` and is yours to edit. When it covers the same topic as a pack skill, the Code Writer and Code Reviewer follow **your** skill.

```sh
skill-factory list
```

```sh
skill-factory get -p coder
```

Then ask your agent to run a generator, e.g. `/create-clean-code-skill` in Claude Code. It writes the real skill (for example `.agents/skills/clean-code/`) and trial-runs it on your code.

| Package | Generators (`create-…-skill`) |
|---|---|
| `coder` | clean-architecture · incremental-implementation · clean-code · unit-testing · code-simplification · bug-hunt · root-cause-debugging · secure-coding-standards · database-migrations · git-workflow |
| `reviewer` | code-review · bug-hunt · clean-architecture · clean-code · unit-testing · secure-coding-standards · database-migrations · security-review · git-workflow |
| `security` | secure-coding-standards · security-review |
| `quality` | quality-planning · quality-environment · quality-acceptance · quality-reporting · visual-quality |

| Command | What it does |
|---|---|
| `skill-factory list [-p <package>] [--json]` | List generators with version, package and scope |
| `skill-factory get <name> [<name>…]` | Copy one or more generators (`clean-code` or `create-clean-code-skill`) |
| `skill-factory get -p <package>` | Copy a whole package |
| `skill-factory get .` | Copy everything |

`get` writes the generator to `.agents/skills/create-*-skill/`, a shared core to `.agents/skill-factory-core/`, and a link under `.claude/skills/` so Claude Code can run it. Use `--force` to refresh existing copies and `--workspace PATH` to target another folder. Copies you already have are never overwritten without `--force`; compare them with a newer generator and keep what you want. Details: [Skill Factory guide](docs/guides/skill-factory.md).


## Working on Coder Nexus

Requirements: Python 3.12+, [`uv`](https://docs.astral.sh/uv/), Node.js (for packaging).

```sh
uv sync
```

```sh
uv run pytest -q
```

```sh
uv run coder-nexus install-plugin --pack flutter --workspace /path/to/project
```

```sh
npx @vscode/vsce package --no-dependencies --readme-path README.extension.md
```

| Path | Content |
|---|---|
| `src/coder_nexus/` | CLI and MCP server |
| `src/skill_factory/` | `skill-factory` CLI and the generator library |
| `plugins/` | Agent roles, skills and stack packs (built by `python -m coder_nexus.plugin_build`) |
| `extension.js` | VS Code extension |
| `docs/guides/` | Detailed guides |
| `README.extension.md` | Page shown on the extension marketplace |

Releases are published by pushing a `vX.Y.Z` tag.

## Ground rules for agents

- Agents cannot approve their own gates.
- Task tracker and Figma access is read-only.
- A result is reported as `PASS` only with evidence. Otherwise it stays `BLOCKED`, `NOT_RUN` or `UNVERIFIED`.
