## 2. Decisions already agreed with the user (do not re-open)

**Huly** (live server `https://huly.imespro.ai`, verified):
- REST `find-all` omits the queried attributes from rows → client re-injects them. Rich text = `GET /files/<ws>?file=<blob>` (the collaborator RPC returns unrelated sample content — never use it).
- Status name/category via `tracker:class:IssueStatus`; closed = WON/LOST. Priority enum 0 none, 1 urgent, 2 high, 3 medium, 4 low.
- Comment author: `createdBy` → `contact:class:SocialIdentity.attachedTo` → Person. Logged-in user: JWT `account` → Person `personUuid`.
- PO documents (`document:class:Document`) are often not visible to the dev account → report UNREACHABLE, ask the user; never guess.
- Downloads go to `<client>/.superpowers/sources/<ISSUE-ID>/`, git-ignored via its own `.gitignore`.

**Specs**:
- Goals first: source inventory → 1–3 outcome goals (G-NN, CONFIRMED, cite D-NN) asked as the first question; every BR/AC/design element/phase serves a goal (validator REQ-005, DESIGN-007, PLAN-V-010).
- Job type asked first for tickets in progress / Dev Done / QA / released / canceled (change, bug fix, verification, docs).
- Stack with no installed pack (e.g. .NET) → `BLOCKED — out of plugin scope`, listed as non-goal.
- Parent ticket: one spec; children are requirement sources and planning input, not one phase each; parent coverage table, ask once about parts with no child. Child ticket: scoped to itself, parent = context.

**UI/UX design** (full plan: §3):
- Every user-visible change needs an approved UI/UX design before technical design. If the ticket has no FE workflow, ask it — never invent it.
- Model: Goal ← Workflow (W-NN, user-confirmed steps) → Step → Screen (S-NN, static HTML with states). Goals checked per workflow, not per screen.
- Lives in the work item only when needed: `.superpowers/work-items/<slug>/vN/design-uiux/`. `.superpowers/ux/` holds only shared things (design-system.json, viewports.json, generated kit/, screen-catalog.md, current/ screenshots, gallery.html).
- `uiux.md` is the source of truth; `index.html` reads `data/flows.js` generated by `coder-nexus ux sync`.
- Viewports asked once per project. Design source: app-ui-kit (imespro) → client theme → Material 3 (+ ask brand/font). Only kit classes; anything else is `new-component` + `components/C-NN`.
- Approved revision = Visual AC; implementation is compared with it at the same viewport.
