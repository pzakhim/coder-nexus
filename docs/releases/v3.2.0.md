# Coder Nexus v3.2.0 Release Notes

## Summary

Coder Nexus 3.2.0 establishes a strict separation between **Core** (neutral process & cross-role handshakes) and **Stack Packs** (stack-specific language rules, frameworks, and idioms), standardizes formal skill names across the ecosystem, and enforces slot completeness and generator traceability via `generated_from`.

> [!WARNING]
> **Breaking Change: Skill Renames & Deletions**
> Skills with legacy names have been removed or renamed. After running plugin sync / update in your workspace, skills with old names will disappear. Update any custom agent prompts or scripts referencing legacy skill names according to the mapping table below.

## 2. Core vs Pack Architectural Separation

The 6 language- and framework-specific skills have been completely removed from `plugins/core/` and are now mandatory slots provided by each stack pack:
1. `clean-code`
2. `secure-coding-standards`
3. `code-simplification`
4. `unit-testing` (incorporates `test-first` loop and when-first matrix)
5. `root-cause-debugging`
6. `bug-hunt`

Each stack pack (`flutter`, `backend`) implements these skills conforming to the Skill Factory generator standards:
- **Flutter Pack:** Effective Dart, `flutter_lints`, and read-only integration with iMESPro packages (`app_core`, `app_util`, `app_ui_kit`).
- **Backend Pack:** Python 3.12+, FastAPI, SQLAlchemy async, and pytest conventions.

---

## 3. Slot Requirements & Traceability (`generated_from`)

- **Enforced Required Slots:** Build fails if any stack pack is missing a required slot or marks it `not_applicable`.
- **`generated_from` Registry:** `pack.json` declares the exact generator name and version used to generate each slot (e.g. `"clean-code": "create-clean-code-skill@1.0.0"`), verified continuously by the test suite.
