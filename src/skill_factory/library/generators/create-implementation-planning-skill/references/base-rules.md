# Base rules (generic, every workspace)

Each rule goes into the generated skill with the workspace's real layout, commands and tools **and its reason**, or is marked "not adopted" with a reason. The fixed `implementation-planning` rules (vertical behavior phases, mandatory PHASE-00, AC coverage, one Code Writer running tasks in order, `validate_plan_slices`) always apply.

| # | Rule | Why | Goes into |
|---|---|---|---|
| IP1 | **Order inside a behavior.** The repository's order for the layers one behavior crosses (for example contract → migration → backend → frontend → wiring); phases stay vertical. | The frontend never waits mid-phase for a backend that is not there. | 01 |
| IP2 | **Task shape.** One task = one file scope + what it produces + one check; size guidance from the repository's history, not an invented number. | The Code Writer knows when a task is done. | 02 |
| IP3 | **Paths from clean-architecture.** File paths in tasks follow the workspace's architecture skill; a plan never invents a new structure. | Plans and architecture stay consistent. | 02 |
| IP4 | **A real check per task.** The exact analyzer, linter or targeted test command, with cwd. | A check that cannot run proves nothing. | 02 |
| IP5 | **PHASE-00 items for this workspace.** Environments, test accounts per role, seed data, mock servers, migrations, feature flags — each `[EXECUTE]` or `[INFO_NOTE]`. | Missing readiness stalls the phase halfway. | 03 |
| IP6 | **Definition of Done per phase.** Checks green, tests for the agreed pass/fail data, migration verified on a disposable database when the phase has one, docs updated where required. | Writer and Reviewer share one finish line. | 04 |
| IP7 | **Branch and hotfix tasks.** Branch, base and merge targets come from the `git-preflight` `D-NN`; a production hotfix has explicit tasks for every line that must receive it; merges into production and tags are commands for the user, not tasks. | The plan matches how code reaches each environment. | 01, 04 |
| IP8 | **Out-of-workspace work is a handoff.** Changes in another repository, infrastructure or another team's system are a handoff or `BLOCKED`, never a Code Writer task. | Agents do not change what they may not change. | 03 |
| IP9 | **Unknowns early.** A technical uncertainty is settled in PHASE-00 or the first phase (a probe, a spike), not discovered in the last one. | Risks surface while change is cheap. | 01, 03 |
| IP10 | **Global constraints.** Exact values the approved `requirements.md` / `design.md` pin for the whole item (limits, version floors, formats, copy, naming, platform targets) are copied once, verbatim and with their source ID (`BR-NN`, `D-NN`, design section), into a `## Global constraints` section of `implementation-plan.md`, above `## AC coverage`. Every task inherits them; tasks do not restate or paraphrase them. A value the spec does not pin is a `Q-NN` before Gate 3, never an agent default. | A Code Writer reading one task still meets the item-wide limits, with the spec's numbers, not a paraphrase. | 01 |
| IP11 | **Review focus.** Up to five input classes or failure modes the spec implies but no planned check covers (empty or huge input, repeated submit, concurrent edit, lost connection, missing permission), most likely first, in a `## Review focus` section of `implementation-plan.md`. Each line names the input, the expected result taken from the spec or a `D-NN`, and the task that adds the check; an expected result the spec does not give becomes a `Q-NN`. `None found after checking every AC and BR` is written when the check found nothing. | The spec's silence on an input is not permission for it to break; the gap gets an owner and a test before code is written. | 01, 02 |
| IP12 | **Task sizing.** Sizes XS / S / M / L / XL are defined from this repository's history (files and lines of reviewed commits that landed without rework). Split a task that is XL, touches 8 or more files, has "and" in its title, or crosses two subsystems. Split only where a reviewer could reject one task and approve its neighbour; setup, config and docs fold into the task whose result needs them. | Tasks stay reviewable in one sitting, and splits do not produce pieces that prove nothing alone. | 02 |
| IP13 | **High risk first** (extends IP9). After PHASE-00, the vertical behavior with the highest technical or business risk comes first among the phases its dependencies allow. | A failed assumption is found while most of the plan can still change. | 01 |
| IP14 | **Prefactor first.** A behavior-preserving refactor that makes the change easy is the first task of the phase that needs it, inside the approved scope, with the existing tests green as its check; it never mixes in new behavior. | "Make the change easy, then make the easy change" keeps both diffs reviewable. | 01, 02 |
| IP15 | **Expand → migrate → contract for wide renames.** A mechanical change whose blast radius breaks many call sites at once (rename a shared symbol, retype a column) is the one allowed exception to slicing by behavior: an expand task adds the new form beside the old, each migrate batch (per package or folder, sized by blast radius) is its own task, a contract task removes the old form after the last batch. Every task keeps the checks green; tasks stay inside the behavior phase that needs them where possible. Schema changes follow `database-migrations`. | No single task breaks the build, and each batch can be reviewed and reverted alone. | 01, 02 |
| IP16 | **Signatures, not bodies.** A task gives file paths, exact signatures (name, parameters, return type) of what it produces, the values the spec pins, and the test names with their assertions. No transcribed function bodies, except an algorithm the signature and tests do not determine or exact copy the spec fixes. A plan longer than the code it describes has written the code. | The plan carries decisions the Code Writer cannot make alone; a transcribed body goes stale and hides the decisions. | 02 |
| IP17 | **Tests and docs inside each phase.** Each phase's tasks include the tests and the doc updates for that behavior; there is never a final testing, docs or polish phase. | A phase is not done without its tests (IP6), and a final testing phase is a horizontal slice. | 01, 04 |

**Never "not adopted":** IP3, IP4, IP8, IP17.
