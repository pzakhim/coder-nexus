# Base Rules (`RS1`–`RS10`, Mandatory Compliance)

Every rule `RS1`–`RS10` is **mandatory compliance** and goes into the generated skill adapted to the workspace's real sources, terms, and examples **with its reason**. The fixed `grilling` laws (draft first, confirm every inference, 0 open questions, one question at a time) always apply; these rules supply workspace-specific content inside them.

## Unified Gate Scales (`shared_contracts/flags_and_statuses.md`)

- **Deterministic CLI Gates (`PASS` / `FAIL`):** Spec validator (`validate_proposal_spec`) and `rg` pattern audits (banned vague words, banned `domain-knowledge` synonyms, unresolved `Q-NN`, and `AC-NN` traceability) evaluate strictly to `PASS` (`exit 0` / zero matches) or `FAIL`.
- **Gate 1 Review Severities (`BLOCKER` / `MAJOR` / `MINOR`):**
  - `BLOCKER`: Missing source inventory, unresolved `Q-NN`, `[Conflict]` between `BR-NN`/`AC-NN` and `D-NN`, unverified `REMOVED` migration note, or banned synonym/vague word that masks behavior. Blocks Gate 1 approval.
  - `MAJOR`: `[Gap]` in a mandatory domain edge-case category, unmeasurable `G-NN` success signal, or `[Ambiguity]` in `BR-NN`/`AC-NN` observable state. Blocks Gate 1 approval until resolved via `Q-NN`.
  - `MINOR`: Wording polish or formatting improvement that does not alter testability or scope.

## Job Types

Gate 1 review questions (`RS6`) and change deltas (`RS10`) follow the work-item Types: `feature`, `bugfix`, `refactor`, `optimization`, `migration`, `maintenance`, `investigation`, `documentation`. A `"change"` is a `feature` or `refactor` delivered as a new `vN` (`v2+`) with `change-impact.md`; a `"verification"` is an `investigation` that produces `verification.md` findings only, with zero code changes. Include only the job types the workspace uses.
