# Base Rules — API Contract Design (Mandatory Compliance)

Every generated `api-contract-design` skill must enforce all 9 base rules (**AP1–AP9**) alongside `shared_contracts/api_handshake_protocol.md` and `shared_contracts/flags_and_statuses.md`:

| # | Rule | Why It Is Mandatory | Target Reference |
|---|---|---|---|
| **AP1** | **Contract-first, single source of truth.** Approve endpoint contracts in `design.md` (Gate 2) before coding; generate the delivered contract snapshot (`openapi.json`) directly from code (never hand-edit it). | Prevents silent drift between Backend implementation, Frontend clients, and mock servers. | `SKILL`, `01`, `03` |
| **AP2** | **Consistent route naming & separate input/output schemas.** Use consistent resource paths, HTTP verbs, and stable `operationId`s/tags; define separate input (`Create`/`Update` with `extra="forbid"`) and output (`Read`) schemas; never expose raw ORM models or untyped `dict`/`Any`. | Prevents mass assignment (`extra="forbid"`), accidental column leaks, and broken generated client SDKs. | `01` |
| **AP3** | **Single centralized error envelope & explicit status codes.** Define one error response schema (`code`, `message`, `fields`, `request_id`) once and declare all returned status codes (`200`, `201`, `204`, `401`, `403`, `404`, `409`, `422`, `429`) on routes/routers. | Enables clients to handle errors uniformly without parsing human message strings; prevents stack-trace leaks. | `01` |
| **AP4** | **Bounded pagination, deterministic ordering & allow-listed filters.** Enforce a maximum page size (`le=100`), include a unique tie-breaker key (`id`) in `ORDER BY`, and validate filter/sort fields against an explicit allow-list (`Literal[...]`). | Prevents unbounded memory/DB exhaustion (OWASP API4), duplicate/missing rows across pages, and SQL injection. | `01` |
| **AP5** | **Per-endpoint authentication, RBAC & anti-IDOR data scopes.** Declare security dependencies so every protected operation carries `security` in the generated contract; enforce role checks (`403`) and tenant/owner scope filters in services (returning `404` when a resource exists outside the caller's scope). | Prevents unauthenticated access, privilege escalation, and cross-tenant ID enumeration (IDOR). | `02` |
| **AP6** | **Additive-first compatibility, Hyrum's Law & One-Version Rule.** Classify every contract diff as Additive vs. Breaking. Any breaking change (or observable behavior change under Hyrum's Law) requires an approved `D-NN`, a backward-compatible transition path (`deprecated=True` + removal date), and a single live API version (One-Version Rule). | Keeps deployed mobile and web clients working without proliferating parallel `/v2`, `/v3` codebases. | `02` |
| **AP7** | **Automated snapshot diffing & client/mock synchronization.** Generate `contracts/openapi.json` at `REVIEW_REVISION`, diff against `contracts/openapi.base.json` (`BASE_REVISION`), record every hunk in `contracts/contract-change.md`, and keep client contracts (`api_contract.json`) and mocks synchronized. | Surfaces unplanned contract changes before review or client integration fails. | `03` |
| **AP8** | **Safe retried mutations (`Idempotency-Key`).** Endpoints subject to client retries must claim an intent-scoped `Idempotency-Key` atomically (unique constraint), reject a changed payload under the same key (`409`/`422`), define a deterministic in-flight duplicate response, and treat client timeouts as unknown outcomes. | Prevents duplicate orders, double charges, or corrupted state when mobile/web clients retry over unstable networks. | `01` |
| **AP9** | **Honest contract provenance (`FE_MOCKOON` vs `BE_LIVE`).** Explicitly state whether contract verification ran against a generated snapshot, a mock server (`FE_MOCKOON`), or a live deployed backend (`BE_LIVE`). | Mock or snapshot checks never substitute for live end-to-end integration proof. | `SKILL`, `03` |
