# Base Rules — Quality Environment (Mandatory Compliance)

Every generated `quality-environment` skill must enforce all 14 base rules (**E1–E14**) adapted to the workspace's services, commands, data isolation rules, and external providers:

| # | Rule | Why It Is Mandatory | Target Reference |
|---|---|---|---|
| **E1** | **Know the service topology.** Document all services, ports, start/stop commands (`cwd`), health checks, and start order (datastore → API/service → background workers → client/UI). | Guessing commands starts the wrong process or leaves dependencies unready. | `01` |
| **E2** | **Probe before starting; never stop what you did not start.** Check listening ports and health endpoints first and reuse a healthy running stack; never stop, restart, or reset a stack someone else started (another agent or the user). | Killing someone else's stack destroys their work in progress. | `01`, `SKILL` |
| **E3** | **Start in the background, capture logs, record ownership.** Record the PIDs or container IDs you started and where their logs are written; stop only those processes. | Logs provide execution evidence; explicit ownership makes cleanup safe. | `01` |
| **E4** | **Verify readiness before testing.** Wait for health endpoints or initial application response with a bounded timeout; slow initial compilations are normal, unbounded waits are not. | Testing a half-started stack produces false failures. | `01`, `03` |
| **E5** | **Isolated test data.** Use dedicated tenant/workspace/run IDs or resettable local fixtures; never use production data; never run commands that clone, reset, or overwrite shared business data without explicit approval. | Shared or production data corrupts test results and causes real damage. | `02`, `SKILL` |
| **E6** | **Per-role test accounts without leaked credentials.** Maintain seeded test users for each role and environment the test plan requires; load credentials from approved local config, never print or paste secret values, and never use real user accounts. | Permission matrices require every role; real accounts leak and get locked. | `02` |
| **E7** | **External providers: sandbox first, labelled stub second.** Use provider sandboxes where available; otherwise stub at the network edge with documented scenarios (success, validation error, auth error, server error, timeout); label every result from a stub as `stubbed: <provider>`. | A `PASS` against an unlabelled stub is a false `PASS` for provider integration. | `02`, `SKILL` |
| **E8** | **Schema at the reviewed revision.** Apply the reviewed revision's migrations to the local/disposable database (per `database-migrations`) before running acceptance tests. | Old schema with new code fails for reasons unrelated to the feature under test. | `01` |
| **E9** | **Run the exact reviewed revision.** Checkout, install dependencies, build, and restart the services you own at the exact revision under test, and record the commit SHA. | Testing a different revision proves nothing about the reviewed change. | `01` |
| **E10** | **Environment matrix clarity.** Document which environments the test plan requires (e.g., logical environment selectors inside the app vs. physical target databases) and how to switch between them safely. | Confusing an in-app selector with a separate database breaks test isolation. | `02` |
| **E11** | **Post-run cleanup.** Remove test data created during the run when required by the workspace, stop only the processes you started, and retain logs for evidence. | Leftover data and orphan processes poison subsequent runs. | `03` |
| **E12** | **Environment failure = `BLOCKED`.** When a service is down, an unowned port is unhealthy, credentials are missing, or a provider has no sandbox/stub, report `BLOCKED` with evidence and owner — never work around environment failures by modifying application code. | Modifying application code to bypass an environment failure alters the system under test. | `03`, `SKILL` |
| **E13** | **Secrets stay local.** Environment files remain local and git-ignored; secret values are never echoed, logged, or included in test reports. | Test reports and logs are shared across teams and artifacts. | `02`, `03` |
| **E14** | **Record the environment in evidence.** Capture the revision SHA, running services and versions, seed/isolation ID, stubs (`stubbed: <provider>`), test account role names, and ownership/start timestamp alongside test results. | Results without their environment record cannot be reproduced or audited. | `03` |
