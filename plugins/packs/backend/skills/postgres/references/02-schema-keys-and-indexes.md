# 02 — Schema: keys, types, constraints and indexes

How SQLAlchemy 2 models map to PostgreSQL. The workspace's existing conventions win when they already exist (record them in `codebase-notes.md`); these are the defaults for new tables. Every change here ships as an Alembic revision (`backend-database-migrations`).

## Naming convention (once, on the declarative base)

```python
NAMING = {
    "ix": "ix_%(table_name)s_%(column_0_N_name)s",
    "uq": "uq_%(table_name)s_%(column_0_N_name)s",
    "ck": "ck_%(table_name)s_%(constraint_name)s",
    "fk": "fk_%(table_name)s_%(column_0_name)s_%(referred_table_name)s",
    "pk": "pk_%(table_name)s",
}

class Base(DeclarativeBase):
    metadata = MetaData(naming_convention=NAMING)
```

Reason: Alembic autogenerate only tracks named constraints, and a rename or drop in a later migration needs the exact name on every environment.

## Keys

| Need | Model | Reason |
|---|---|---|
| Internal id, single database | `id: Mapped[int] = mapped_column(BigInteger, Identity(always=True), primary_key=True)` | SQL-standard identity, 8 bytes, ordered inserts; `serial` is legacy |
| Id exposed in URLs, generated by clients or across services | `id: Mapped[uuid.UUID] = mapped_column(Uuid, primary_key=True, default=uuid7_or_uuid4)` | Not enumerable; prefer time-ordered UUIDv7 (`uuidv7()` on PostgreSQL 18+, or generated in Python) because random v4 keys scatter B-tree inserts |
| Both | internal `BIGINT` identity key + a unique `public_id UUID` column | Joins stay small; the API never exposes the sequence |

Never change a key type of an existing populated table in one migration (see `backend-database-migrations` expand → backfill → contract). Vendored detail: `schema-primary-keys.md`.

## Column types

| Data | Use | Avoid | Reason |
|---|---|---|---|
| Event time | `DateTime(timezone=True)`, `server_default=func.now()` | `DateTime()` (naive) | `timestamptz` stores an absolute instant; naive values break across zones and DST |
| Money, exact decimals | `Numeric(12, 2)` | `Float`, `money` | Floats round; `money` depends on locale |
| Text | `Text` or `String`, `CheckConstraint("char_length(x) <= n")` when the limit is a business rule | `CHAR(n)` | Same storage; a CHECK states the rule explicitly |
| Small closed set | `Text` + `CheckConstraint` or a lookup table; native `Enum` only for sets that never shrink | Native enum for evolving values | Removing a native enum value needs a type rebuild |
| Optional attributes | `JSONB` (`postgresql.JSONB`) with a GIN index if filtered | `JSON`, or JSONB for core fields | Core fields need constraints and types; `JSON` cannot be indexed well |
| Boolean flags | `Boolean, nullable=False, server_default=false()` | Nullable booleans | Three-valued logic surprises filters |

Identifiers are `snake_case`, unquoted. Vendored detail: `schema-data-types.md`, `schema-lowercase-identifiers.md`.

## Constraints

- `nullable=False` wherever the domain requires a value; `server_default` when existing rows need one.
- Foreign keys state `ondelete` explicitly (`RESTRICT` by default, `CASCADE` only for owned children). Reason: the default `NO ACTION` is rarely a decision anyone made.
- Uniqueness that ignores case uses a unique index on `lower(col)`; one-NULL uniqueness uses `postgresql_nulls_not_distinct=True` (PostgreSQL 15+).
- Multi-tenant tables carry the scope column (`tenant_id`, `owner_id`) from day one and include it in unique constraints and composite indexes. Reason: adding a scope column to a populated table later is a multi-step migration, and every query must filter by it (`{{slot:secure-coding-standards}}`).

## Indexes

Rule: **an index for every foreign key column and every column a query filters, joins or sorts on**, unless the table is known to stay tiny (record why).

```python
class Order(Base):
    __tablename__ = "orders"
    id: Mapped[int] = mapped_column(BigInteger, Identity(always=True), primary_key=True)
    tenant_id: Mapped[int] = mapped_column(ForeignKey("tenants.id", ondelete="RESTRICT"))
    customer_id: Mapped[int] = mapped_column(ForeignKey("customers.id", ondelete="RESTRICT"))
    status: Mapped[str] = mapped_column(Text)
    created_at: Mapped[datetime] = mapped_column(DateTime(timezone=True), server_default=func.now())

    __table_args__ = (
        Index("ix_orders_customer_id", "customer_id"),                         # FK, not indexed automatically
        Index("ix_orders_tenant_id_status_created_at", "tenant_id", "status", "created_at"),  # list filter + sort
        Index("ix_orders_open", "tenant_id", postgresql_where=text("status = 'open'")),       # hot subset
        CheckConstraint("status IN ('open', 'paid', 'cancelled')", name="status_allowed"),
    )
```

| Query shape | Index | Vendored file |
|---|---|---|
| `WHERE a = ? AND b > ? ORDER BY c` | composite `(a, b, c)` — equality columns first, then range/sort | `query-composite-indexes.md` |
| Filter on a hot subset (`status = 'open'`) | partial index with `postgresql_where` | `query-partial-indexes.md` |
| Read only a few columns by key | `postgresql_include=[...]` covering index | `query-covering-indexes.md` |
| JSONB containment, arrays, full text | GIN (`postgresql_using="gin"`) | `advanced-jsonb-indexing.md`, `advanced-full-text-search.md` |
| Large append-only time series | BRIN on the time column | `query-index-types.md` |

- An existing composite index whose leading column is the FK already covers the FK; do not add a duplicate.
- Each index costs write time and storage: add it for a query that exists in the code, and confirm it with a plan ([03](03-query-plans-and-n-plus-one.md)).
- On a populated table the index is created `CONCURRENTLY` in its own migration (`backend-database-migrations`); `Index(...)` in the model only keeps autogenerate in sync.
