# 01 — Alembic Workflow, 3-Tier Authority, and Revision Rules (`A1`–`A9`)

> Topic: Inspecting `alembic.ini` and `alembic/env.py`, enforcing the 3-tier environment authority model (`Local/Disposable` vs `Develop on user request` vs `Staging/Production by DevOps`), reviewing autogenerated files, and enforcing revision rules `A1`–`A9`.

---

## 1. Inspect the Workspace Setup First

Record these facts in `codebase-notes.md` before writing or running any revision:

| Fact | Where to Inspect | Why It Matters |
|---|---|---|
| **Command prefix & cwd** | `uv.lock` → `uv run`; `poetry.lock` → `poetry run`; `.venv/bin/alembic`; directory holding `alembic.ini` | Running a global `alembic` uses the wrong environment or wrong `script_location` |
| **How `DATABASE_URL` is loaded** | `alembic/env.py` (`config.set_main_option`, settings object, `DATABASE_URL` env var) | Determines how to point Alembic at the disposable DB without editing shared `.env` |
| **Async vs. sync `env.py`** | `async_engine_from_config` + `connection.run_sync(do_run_migrations)` | Async `env.py` requires `postgresql+asyncpg://`; sync requires a sync driver |
| **`target_metadata`** | `env.py` imports `Base.metadata` and every `app/models/*` module | An unimported model is invisible to autogenerate, which then proposes dropping its table |
| **Transaction mode** | `transaction_per_migration` in `context.configure` | `autocommit_block()` commits whatever ran before it in that transaction |
| **Existing revisions** | Newest 3–5 files in `alembic/versions/` | Confirms constraint naming convention (`backend-postgres`) and revision style |

## 2. 3-Tier Environment Authority Protocol

Before running any command that writes to a database, check the target hostname (`python -c "import os,urllib.parse as u; print(u.urlsplit(os.environ['DATABASE_URL']).hostname)"` — never `cat .env` into the transcript):

1. **Tier 1 — Local / Disposable DB (`localhost`, `127.0.0.1`, compose test service, throwaway DB)**:
   - The Backend Agent runs `alembic upgrade` / `downgrade` autonomously for development and `V1`–`V8` verification.
2. **Tier 2 — Develop Environment (`develop`)**:
   - The Backend Agent **may** run schema and data migrations on `develop` **ONLY when the user explicitly requests or approves it in the current session** (e.g., user explicitly says *"migrate lên develop"* or confirms via `ask_question`).
   - **Never** run migrations against `develop` automatically without the user's explicit instruction.
   - Even when the agent migrates `develop` on user request, the agent **must** still generate the complete **DevOps Migration Handoff Packet (`migration-handoff.md`)** documenting all changes, reasons, and execution steps.
3. **Tier 3 — Staging & Production (`staging`, `production`)**:
   - **Strictly executed by DevOps** — the Backend Agent **never** runs `alembic upgrade`, `downgrade`, or data backfill commands against `staging` or `production`, even if credentials exist.
   - The Backend Agent prepares `migration-handoff.md` (`READY_FOR_HANDOFF`) so the user can hand it over to DevOps.

## 3. Autogenerate + Mandatory Hand-Review

```bash
# cwd: backend root, DATABASE_URL pointing at local/disposable DB already at head
uv run alembic upgrade head
uv run alembic revision --autogenerate -m "add customer_id index to orders"
```

Read and correct every line of the generated file before running it:

| What `--autogenerate` Emits | Mandatory Hand-Review Correction |
|---|---|
| Added/removed tables, columns, nullability, FKs, types | Confirm each belongs to this task; delete unrelated drift from other branches |
| Column/table **rename** emitted as `drop_column` + `add_column` | Rewrite as `op.alter_column(..., new_column_name=...)` or as `Expand → Backfill → Contract` ([02](02-safe-schema-changes-and-backfills.md)); `drop` + `add` destroys data |
| Anonymous constraints, `CHECK` constraints, `server_default` changes | Add explicitly with deterministic names (`MetaData(naming_convention=...)` in `backend-postgres`) |
| Plain `op.create_index(...)` on a populated table | Rewrite inside `with op.get_context().autocommit_block():` with `postgresql_concurrently=True` ([02](02-safe-schema-changes-and-backfills.md)) |
| `nullable=False` on a new column of a populated table | Add a constant `server_default` or split into `Expand (nullable) → Backfill → Contract (NOT NULL)` |
| Enum value additions | Write `op.execute("ALTER TYPE ... ADD VALUE IF NOT EXISTS '...'")`; never drop an enum value still stored |

## 4. Mandatory Rules for Every Revision (`A1`–`A9`)

| # | Rule | Reason |
|---|---|---|
| **A1** | **One revision per logical step** (separate revisions for `expand`, `backfill`, and `contract`; separate revision for `CONCURRENTLY` index builds). | Keeps each step atomic, reviewable, and independently reversible. |
| **A2** | **Imperative, lowercase message slug** (`add customer_id index to orders`, `backfill orders currency`). | Becomes the revision filename and the history line DevOps reads. |
| **A3** | **Single linear head** (`down_revision` points to current head; `uv run alembic heads` outputs 1 line). | Multiple heads break `upgrade head` or execute in undefined order. |
| **A4** | **Re-point unshared revisions on rebase**; use `alembic merge` only when both branches were already applied to a shared environment. | Preserves linear history unless branches diverged in shared targets. |
| **A5** | **Self-contained revisions (never import `app.models` or `app.services`)**. Define lightweight table stubs with `sa.table("orders", sa.column("id"), ...)` or `op.execute(sa.text(...))`. | Application models change over time; importing today's ORM model breaks historical migrations on fresh installs. |
| **A6** | **Real `downgrade()`**. Reverse the schema step; if a contract step is data-lossy, restore the table/column structure and state `"Irreversible data step — restore from backup"` in the docstring and `migration-handoff.md`. | Verification tests `downgrade -1`; DevOps must know what `downgrade` restores vs. what requires a backup restore. |
| **A7** | **Lock guard first**. Start `upgrade()` with `op.execute("SET LOCAL lock_timeout = '5s'")` on DDL touching existing tables. | Prevents DDL waiting on a lock from queuing all traffic behind it ([02](02-safe-schema-changes-and-backfills.md)). |
| **A8** | **Parameterized SQL only** (`sa.text("... WHERE status = :v")`, never f-strings). | Prevents SQL injection and plan cache bloat. |
| **A9** | **Zero secrets or environment-specific literals** in revision files. | Revisions run across all environments and are committed to git. |
