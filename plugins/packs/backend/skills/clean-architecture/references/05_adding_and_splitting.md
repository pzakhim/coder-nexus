# 05 — Adding a feature and splitting long files

## 1. Add a resource or an endpoint

Each step is a task in the approved phase with its own check (`incremental-implementation`; task fields in `work-item-contract` → `plan-and-task-contract.md`). Skip steps the behavior does not need: an endpoint on an existing table has no migration or model step.

| # | Step | Files | Task check (cwd: backend root, with the workspace prefix) | Expected |
|---|---|---|---|---|
| 1 | ORM model | `app/models/<resource>.py`, `app/models/__init__.py` (one import line) | `mypy app/models` | `Success: no issues found` |
| 2 | Migration for the new tables/columns (autogenerated from the model, then reviewed by hand) | `alembic/versions/<rev>_<slug>.py` | `alembic upgrade head` then `alembic downgrade -1` then `alembic upgrade head` on the test database | Each command exits 0; details in [database-migrations](../../database-migrations/SKILL.md) |
| 3 | Repository | `app/repositories/<resource>.py`, `tests/repositories/test_<resource>.py` | `pytest tests/repositories/test_<resource>.py -q` | Named tests pass against the test database (red run first when `{{slot:unit-testing}}` applies) |
| 4 | Schemas | `app/schemas/<resource>.py` | `mypy app/schemas` | No issues; field names and types equal the API contract in `design.md` |
| 5 | Service | `app/services/<resource>.py`, `tests/services/test_<resource>.py` | `pytest tests/services/test_<resource>.py -q` | Pass, including the forbidden and not-found cases from the design's test data table |
| 6 | Router + wiring | `app/api/routers/<resource>.py`, `app/api/deps.py` (service dependency), `app/main.py` (`include_router`) | `pytest tests/api/routers/test_<resource>.py -q` | Status codes and bodies equal the Pass/Default/Fail/Empty rows of the design |
| 7 | Error mapping (only for a new error class) | `app/core/errors.py`, `app/api/error_handlers.py` | The router test of the failing case | Contract status and error `code` |

After the last task of the phase run the phase checks from `{{slot:verification}}` (`ruff check .`, `ruff format --check .`, `mypy app`, `pytest -q`), and the dependency check from [02_dependency_rules.md](02_dependency_rules.md).

Not allowed while adding: placeholder files for later phases, empty services "for symmetry", a second session dependency, a new settings field with a made-up default, a `Protocol` with one implementation (A10).

## 2. When a file is too long

Thresholds come from the workspace's clean-code skill, else `{{slot:clean-code}}` CC7 (~30 lines per function). For files, split when a file holds more than one reason to change, or passes ~300 lines of new or changed code. Split only inside the task that is already changing the file, or as a planned prefactor task (`implementation-planning`), never as a drive-by.

| File | Split into | Keep |
|---|---|---|
| `app/api/routers/orders.py` | Sub-resource routers: `app/api/routers/order_lines.py` with `prefix="/orders/{order_id}/lines"` | One router per URL prefix; each included in `main.py` |
| `app/services/orders.py` | Package `app/services/orders/` with one module per use case group (`placement.py` → `OrderPlacementService`, `cancellation.py`) and an **empty** `__init__.py` | Callers import from the defining module; `app/api/deps.py` gets one builder per new service class |
| `app/repositories/orders.py` | Per aggregate (`order_lines.py`), and heavy read queries into `app/repositories/order_reports.py` returning plain rows | Writes stay with the aggregate's repository |
| `app/schemas/orders.py` | Package `app/schemas/orders/` with `requests.py` and `responses.py` | Names unchanged (`OrderCreate`, `OrderRead`), so the contract does not move |
| `app/models/orders.py` | One module per table | `app/models/__init__.py` imports the new module |

Rules for every split:

- Move code without changing behavior, in its own task, and run the same tests before and after (identical pass list). Reason: a split mixed with a behavior change cannot be reviewed.
- Update every caller in the same task and delete the old location; no alias module that re-exports old names (core `clean-code` CC2).
- No `utils.py`, `helpers.py`, `common.py`: name the module for what it does, inside the owning layer (core `clean-code` CC4).

## 3. Feature-first workspaces

If the verified tree is `app/modules/<feature>/{router,schemas,service,repository,models}.py`, the same rules apply per feature folder: the role table in [01_folder_layout.md](01_folder_layout.md) maps file-for-file, the dependency direction holds inside the module, and a module reaches another only through that module's service. The import-linter `layers` contract then uses `containers = ["app.modules.orders", ...]`.
