## Flutter rules

- **Profile & Scans (Step 1A)**: Resolve `architecture_profile.mode` (`imespro` / `external-structured` / `external-standard`) **first** via `{{slot:architecture-design}}` (`references/01-context-scan-and-decisions.md` + active profile contract) and execute the 6 scans (`pubspec.yaml`, workspace foundations, Router, DI, module code, `get_ux_error_patterns`).
- **FE Data Pipeline & `design.md` Flutter specifics**:
  - Data pipeline: `RemoteDataSource` (`ApiService`/HTTP client), `Model.fromJson`, `RepoImpl`, `UseCase`, DI under `lib/modules/<feature>/` (pruned from `get_project_structure`).
  - Screen/State/Mapping: specify screen base (`BaseScreen` in `imespro`, client base in `external-structured`, standard widget in `external-standard`), Cubit states/methods, Mockoon design (`references/02-screen-state-api-and-ui.md`), and `Core usage` (`imespro`) / `Client Core Mapping` (`external-structured`) / UI spec (`external-standard`).
  - `## UI/UX mapping` (`{{slot:ui-kit-mapping}}`, `references/03-widget-mapping-and-design-handoff.md` + active profile contract): audit Figma (`tokens.json`, `<stem>.spec.json`, `<stem>-SNN.png`), HTML sitemap (`sitemap/screens/*.png`, `*.spec.json`, aligning elements to active profile tokens without requiring `tokens.json`), or codebase tokens (`CODEBASE_ONLY`); map `S-NN` → screen class/route/args, tokens/nodes → widgets, and `C-NN` → `lib/modules/<feature>/presentation/widgets/` (or shared folder when 2+ modules need it), surfacing every `Core gap` at Gate 2.
- **Task Checks & Review DoD**: `flutter analyze`, targeted unit tests (`test/modules/<feature>/` covering UseCases, Mappers, Cubit Pass/Default, Fail, Empty), and zero-error `flutter analyze`.
- **Gate 3 Flutter `test-plan.md` (Hybrid E2E) & `final_qa` L3 Escalation**:
  - Define live sequential **`E2E-01..E2E-N`** scenarios in `vN/test-plan.md` for `test_runner` across the **Flutter Verification Ladder**: (1) `flutter analyze`, widget tests, and any existing `integration_test/` suites, (2) live runtime execution & `W-NN` navigation (Web `browser` subagent / `chrome-devtools` MCP or native simulator/emulator), (3) all 4 Visual States (`Loading`, `Content`, `Empty`, `Error`), (4) Golden comparison (strictly **without** `--update-goldens`) + multimodal `read_file` comparison against Figma `<stem>-SNN.png` OR HTML sitemap `sitemap/screens/*.png` (`{{slot:visual-quality}}`), and (5) profile invariants (`imespro`: `BaseScreen` route/responsive hooks, `ListViewPaging`, `app_ui_kit`).
  - **Hybrid E2E optional `integration_test/`**: Ask once in Gate 3 whether to run live `E2E-01..N` only or also schedule local **`integration_test/<feature>_e2e_test.dart`** authoring tasks for **`code_writer`** (which `test_runner` executes read-only during `final_qa`).
  - When `bug_fixer` raises an `L3` `PCR-NN.md` during `final_qa` (`../app-*` `Core gap`, `BaseScreen`, `lib/core/`/`lib/shared/`, or Router/DI/Cubit state-matrix flaw), resolve via `change-control` so **`code_writer`** implements the amended task(s) and `code_reviewer` approves before `test_runner` re-verifies `E2E-01..E2E-N` from start to finish.
