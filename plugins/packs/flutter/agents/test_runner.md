## Flutter rules

- **Source & test folders (strictly read-only)**: Never modify `lib/`, `test/`, or `integration_test/`; tick only `- [x] **E2E-i**` and `Evidence:` in `vN/test-plan.md`, write evidence ONLY under `vN/evidence/final_qa/<revision>/` (never write to `.superpowers/ux/`), and never run `--update-goldens`.
- **Sequential Flutter Hybrid E2E Verification Ladder (`test-plan.md` `E2E-01..E2E-N` — Fail-Fast)**:
  - Execute `E2E-01` → `E2E-02` → ... → `E2E-N` in `vN/test-plan.md` sequentially, adapting the harness per `{{slot:verification}}` and `{{slot:visual-quality}}` for the resolved `architecture_profile.mode`:
    1. **Rung 1 — Static, Widget & Existing Local `integration_test/` Suites**: Run `flutter analyze`, targeted widget tests (`flutter test`), and **execute any existing local `integration_test/` suites** (`flutter test integration_test/<feature>_e2e_test.dart`) authored by `code_writer` when scheduled in the Gate 3 plan.
    2. **Rung 2 — Live `E2E-01..N` Execution & Independent 4-State Capture**: Launch the real Client target (`mockoon-cli` for `MOCKOON_MOCKED`, live backend for `BE_API_READY`) and drive live `E2E-01..E2E-N` via **Antigravity builtin `browser` subagent / `chrome-devtools` MCP** *(when configured)* (Flutter Web/Chrome) OR **native simulator/emulator capture** (`xcrun simctl`, `adb shell input`/`screencap`, `screencapture`), saving independent 4-state `.png`s (`Loading`, `Content`, `Empty`, `Error`) ONLY under `vN/evidence/final_qa/<revision>/visual/`.
    3. **Rung 3 — Profile & UI Kit Invariants**: Under `imespro`, verify `BaseScreen` route observer and responsive hooks, `ListViewPaging` auto-load/pull-to-refresh, and `app_ui_kit` interactions; under `external-standard`, Cubit/BLoC is not required.
    4. **Rung 4 — Golden Tests (Never `--update-goldens`) & Multimodal Visual Fidelity**: Run configured golden tests strictly **without `--update-goldens`** (`--update-goldens` during verification is a `BLOCKER` violation). Load captured `.png`s side-by-side against **Figma (`figma/<stem>-SNN.png`, `tokens.json`, `<stem>.spec.json`) OR HTML sitemap (`sitemap/screens/<id>_<code>.png`, `sitemap/*.spec.json`)** via parallel multimodal **`read_file`**.
  - **Fail-Fast & Canonical Report (`test_runner` ↔ `bug_fixer` ↔ `planning` → `code_writer`)**:
    - Tick `- [x] **E2E-i**` in `vN/test-plan.md` with fresh `flutter test` / runtime screenshot evidence as each scenario passes.
    - If any `E2E-i` fails, **stop immediately (`FAIL-FAST`)**, never alter `test-plan.md` or golden baselines, write canonical **`vN/evidence/final_qa/<revision>/acceptance-report.md`** with `FAILED_AT: E2E-i`, and return `CHANGES_REQUESTED` for **`bug_fixer`** (`L1` max 3 rounds before `L3`, `L2` via `code_reviewer`, or `L3` `PCR-NN.md` → `planning` → `code_writer` → `code_reviewer`).
    - Once fixed on a new revision, re-run `E2E-01` through `E2E-N` from start to finish until 100% pass (`ACCEPTED`).
