## Frontend rules

- **API & Mockoon ownership**: `spec_writer` sets `BE_API_READY`, `MOCKOON_MOCKED`, or `NONE` and business I/O. `planning` writes the technical API contract in `design.md`, designs the FE integration & Data Pipeline (real remote data access only — never fake Client data-source classes unless stack rules allow a mock resource), and for `MOCKOON_MOCKED` agrees the **`Mockoon Trigger & Test Data Table`** via 2-Channel `ask_question` (**Pass/Default `200/201`**, **Empty `[]`**, **Fail `400/401/403/500`**) plus `mocks/<feature>_mockoon.json`.
- **UI & Design System ownership (`{{slot:ui-kit-mapping}}`)**: Audit Figma (`tokens.json`, `<node>.spec.json`, `<stem>-SNN.png`) **OR** HTML sitemap (`sitemap/screens/*.png`, `*.spec.json`) against the codebase UI Kit; map every screen/component in `design.md` (`## UI/UX mapping`, `DESIGN-008`), record any `C-NN` / `Core gap`, specify screen base, `Router`, DI, state contracts, all **4 Visual States** (`Loading`, `Content`, `Empty`, `Error`), and apply `get_ux_error_patterns` + cache policy.
- **`PHASE-00` modes**:
  1. `MOCKOON_MOCKED` (`[EXECUTE]`): executable tasks for `code_writer` to build `mocks/<feature>_mockoon.json`, run `mockoon-cli` + `curl` Pass/Fail smoke checks, pass `code_reviewer`, and tick `[x] PREPARED / COMPLETED`.
  2. `BE_API_READY` (`[INFO_NOTE]`, or `[EXECUTE]` if live probe needed): link `design.md` BE API section and list verified endpoints (do not copy).
- **Context-driven `[REVIEW_CHECKPOINT]`**: Place `- [ ] **[REVIEW_CHECKPOINT: <Screen / Component / Feature unit>]**` right where a `S-NN`, `C-NN`, or UI adjustment materializes (never by rigid task count) and confirm inside the streamlined Gate 3 Channel 1 summary.
- **Gate 3 Frontend `test-plan.md` (`E2E-01..E2E-N`)**: Cover 100% of `AC-NN`, `S-NN`, `W-NN`, and **4 Visual States** (`{{slot:verification}}`, `{{slot:visual-quality}}`) comparing against Figma `<stem>-SNN.png`, HTML sitemap `sitemap/screens/*.png`, or approved baseline; label `MOCKOON_MOCKED` vs `BE_API_READY` per scenario; offer Hybrid E2E choice (live `E2E-01..N` only vs optional local automated E2E suite tasks for `code_writer`). Technical Refinement may adjust mock fixtures.
- **`final_qa` `L3` `PCR-NN.md`**: Resolve UI Kit `Core gap`, shared component/token conflicts, or route/state-matrix flaws via `change-control` (without weakening `AC-NN`/`E2E-NN`), then route amended tasks to `code_writer` → `code_reviewer` → `test_runner`.
