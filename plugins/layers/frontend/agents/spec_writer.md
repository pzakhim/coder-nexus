## Frontend rules

- **Frontend scope**: This workspace is a Frontend Client. Own UI/UX & screen expectations from Figma specs (`figma-intake`) and the API business contract (`BE_API_READY` vs. `MOCKOON_MOCKED`). **NEVER** modify backend files, databases, or remote server code.
- **Stage 1A frontend intake pillars** (in addition to the PO / BA Requirements Source):
  - **UI Screens, UX Flow & Design System Source**: A Figma frame linked in the Huly ticket or user prompt is fetched by `task-detail --download` (or `coder-nexus figma fetch <url>`) into `.superpowers/sources/<ISSUE-ID>/figma/` as file-level `tokens.json` (W3C DTCG), frame-level `<node>.spec.json` (`screens[*].tree`, `components`, `workflows_hint`), per-screen `<node>-SNN.png` renders, `<node>.summary.md`, and raw `<node>.json` when the Client `.env` has `FIGMA_TOKEN`; its source status is `READ`, `NOT_PROVIDED` (no token/link) or `UNREACHABLE` (401/403/404), and only `READ` counts as visual input. Follow `figma-intake`: if `FIGMA_PROVIDED`, extract `S-NN` and `W-NN`; if no Figma link is provided (`CODEBASE_ONLY`), treat as a minor edge-case adjustment on an existing screen (`CHANGED`); if a provided Figma link fails (`UNREACHABLE`), queue a `Q-NN` and never fabricate screens or HTML mockups.
  - **Backend API Integration Source (Binary Check: Does BE API Exist Yet?)**:
    - **Case 1 — BE API Exists (`BE_API_READY`)**: Record the API specification source in `codebase-notes.md` so `planning` consolidates it in `design.md` and `PHASE-00` (`[INFO_NOTE]`).
    - **Case 2 — BE API Does Not Exist (or Missing Endpoints) $\to$ Use Mockoon (`MOCKOON_MOCKED`)**: Lock in the business Input/Output contract in `requirements.md` and `codebase-notes.md` (`## 4. Constraints & External Integrations` & `## 5. Extended Rule Details`) per `shared_contracts/api_handshake_protocol.md`. Downstream, `planning` agrees with the user on the `Mockoon Trigger & Test Data Table` in `design.md` and marks `PHASE-00` (`phases/phase-00-prepare.md`) as `[EXECUTE]`.
- **Stage 1B & 1A-UX**: Cross-check Figma `<node>.spec.json` / `<node>.summary.md` UI flows against provided/estimated APIs and existing Client flows, and populate `## Screens & Visual Sources` (`S-NN`) and `## Workflows` (`W-NN`) in `requirements.md`.
- **Grill dimensions**: the "observable states" dimension covers the Happy Path & **4 Visual States** (`Default/Content`, `Loading`, `Empty`, `Error`) and Multi-Screen state lifecycle.
- **API Boundary**: `spec_writer` owns the business Input/Output of APIs (`BE_API_READY`, `MOCKOON_MOCKED`, or `NONE`) and business Pass/Fail scenarios. `planning` owns the `Mockoon Trigger & Test Data Table`, `PHASE-00` (`phase-00-prepare.md`), and the FE Data Pipeline (the stack's remote data access, models, repositories, use cases and DI).
- **UI / UX & UI Kit Boundary**: `spec_writer` owns screen (`S-NN`) & UX workflow (`W-NN`) requirements and the 4 visual states (`Default/Content`, `Loading`, `Empty`, `Error`). `planning` owns architecture profile resolution, auditing `tokens.json` & `<node>.spec.json` against the codebase UI Kit (`{{slot:ui-kit-mapping}}`), exact widget/component mapping (`C-NN` / `Core gap`), screen base, `Router`, and state contracts in `design.md` (Gate 2).
- **`requirements.md` §4**: name it `## 4. Behavioral Scenarios & Visual States` and include the 4 Visual States.
